**Единица измерения:** минуты  
**Версия Python:** Python 3.10+

Программа хранит список музыкальных занятий в JSON, позволяет добавлять, искать, изменять и удалять записи, показывает статистику и сохраняет результат между запусками. Обязательная версия работает локально и не использует внешние библиотеки.

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `main.py` | Консольное меню, ввод данных и сообщения пользователю. |
| `logic.py` | Валидация записей, добавление, поиск, изменение статуса, удаление и статистика. |
| `storage.py` | Чтение и запись JSON без консольных диалогов. |
| `test_logic.py` | Проверки бизнес-логики и строгих типов. |
| `test_storage.py` | Проверки чтения и записи во временных папках. |
| `data.json` | Небольшой вымышленный набор из пяти музыкальных занятий. |

## Формат данных

`data.json` содержит список объектов с обязательными полями:

```json
{
  "id": 1,
  "title": "Гаммы фортепиано",
  "category": "фортепиано",
  "amount": 45,
  "completed": true
}
```

`id` - положительное целое, уникальное в списке. `title` и `category` - непустые строки. `amount` - целое число минут не меньше нуля; `True` и `False` не принимаются как числа. `completed` - строго логическое значение. Дополнительные поля сохраняются без обработки. Новая запись получает `max(id) + 1`, а при пустом списке - `1`; после удаления существующие ID не перенумеровываются.

В исходном наборе пять записей. Три занятия завершены, два ещё не завершены. Общая продолжительность - `200` минут. Суммы по категориям: `вокал - 25`, `теория - 40`, `фортепиано - 135`.

## Разделение ответственности

`logic.py` не выполняет ввод-вывод. `validate_records()` проверяет весь список до начала работы; `add_record()` очищает края названия и категории, создаёт следующий ID и добавляет статус `False`. `find_records()` ищет подстроку без учёта регистра и отклоняет пустой запрос. `set_completed()` и `delete_record()` возвращают `True` при успешной операции и `False` для неизвестного ID. `statistics()` не меняет записи и возвращает общее количество, числа выполненных и невыполненных занятий, сумму минут и отсортированный словарь сумм по категориям.

`storage.py` использует `json.load()` и `json.dump()` с `encoding="utf-8"`. При загрузке JSON сначала разбирается синтаксис, затем проверяется структура. `main.py` загружает файл до показа меню. При отсутствии `data.json` начинает с пустого списка. При повреждённом JSON, неверной кодировке или структуре выводит причину и завершает запуск без перезаписи входного файла.

## Меню

1. Показать записи - записи выводятся по возрастанию ID, с названием, категорией, минутами и статусом.
2. Добавить запись - пустые поля и неверное количество отклоняются повторным вводом.
3. Найти записи - поиск по непустой подстроке названия без учёта регистра.
4. Изменить статус - явно выбрать `да` для выполненного или `нет` для невыполненного занятия.
5. Удалить запись - удаление выполняется только после подтверждения `да`; любой другой ответ отменяет его.
6. Показать статистику - количество записей, выполненных и невыполненных занятий, общая сумма и суммы по категориям.
7. Сохранить данные - сообщение об успехе появляется только после успешной записи.
8. Выйти - программа предлагает сохранить данные; при ошибке сохранения остаётся в меню.

## Результаты сценариев приёмки

| Сценарий | Результат |
| --- | --- |
| Отсутствует `data.json` | Запуск сообщает об отсутствии файла и открывает пустой список. |
| `data.json` содержит `[]` | Показ записей сообщает `Нет записей`, статистика выводит нулевые количества и сумму. |
| Добавлены занятия на 4 и 2 минуты, второе завершено | Статистика: всего `2`, выполнено `1`, не выполнено `1`, сумма `6`. |
| Название `  Python  ` | В JSON сохраняется `Python`. |
| Поиск `PY` по названию `Python` | Запись находится. |
| Пустое название, `amount=-1`, `amount=abc` | Ввод повторяется, лишняя запись не появляется. |
| Неизвестный ID при изменении статуса | Выводится сообщение, записи не меняются. |
| Отмена удаления | Запись остаётся в списке. |
| Удаление ID 1 из списка ID 1 и 2 | Остаётся ID 2; следующая запись получает ID 3. |
| Сохранение и повторный запуск | Все поля и статусы восстанавливаются из JSON. |
| Повреждённый JSON или повторный ID | Запуск прекращается с сообщением, входной файл не перезаписывается. |
| Ошибка сохранения | Сообщение об успехе не выводится, меню продолжает работу. |

Все автоматические проверки пройдены. Тесты используют `TemporaryDirectory()`, проверяют пустой список, повторяющиеся названия, строгие типы, неизвестный ID, регистронезависимый поиск, статистику по категориям и сохранение с последующей загрузкой.

## Вывод

Проект объединяет условия, циклы, списки и словари, функции, проверку ввода и JSON-хранилище. Данные и операции отделены от консольного интерфейса, поэтому функции можно тестировать без меню. ID сохраняют связь записи с её историей: удаление не приводит к перенумерации. Новая запись проходит ту же проверку структуры, что и загруженный файл.
