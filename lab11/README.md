## Алгоритмы и проверка данных

Функция `validate_todos(data)` сначала проверяет, что корень JSON является списком. Каждая запись должна быть словарём с полями `id`, `userId`, `title` и `completed`. Для идентификаторов используется проверка `type(value) is int`, поэтому `True` не принимается как число. Поле `completed` проверяется через `type(value) is bool`. Идентификаторы задач должны быть положительными и уникальными, заголовок - непустая строка. Дополнительные поля разрешены.

`completion_counts(todos)` создаёт счётчик для каждого встречающегося пользователя до обработки признака `completed`, поэтому пользователь без выполненных задач получает значение `0`. `top_users(counts)` находит максимальное число, возвращает все идентификаторы с этим числом в отсортированном порядке, а для пустого словаря или максимума `0` возвращает `[]`.

Для учебного набора количества равны `{5: 2, 10: 2}`, поэтому лидеры - `[5, 10]`. Завершённые задачи лидеров сохраняются в исходном порядке с идентификаторами `[1, 3, 4, 5]`.

В варианте 12 функция `select_tasks(todos, user_id, parameter)` сначала выбирает задачи пользователя, затем оставляет только завершённые задачи с `id <= parameter`. Порог - неотрицательное целое. Для пользователя `5` и порога `2` результат содержит задачу с `id` `1`; задача `2` не завершена, а задача `5` больше порога. Порядок записей и повторы сохраняются, исходные словари не изменяются.

Основная программа сначала полностью читает и проверяет `todos.json`, затем запрашивает положительный `user_id` и неотрицательный порог. Файлы результатов открываются для записи только после успешного анализа и ввода. Поэтому ошибка JSON, ошибка структуры, отсутствие файла или ошибка доступа не перезаписывают старые `leaders.json` и `selected.json`. Обработчик `JSONDecodeError` расположен раньше общего `ValueError`.

## HTTP-упражнение

`fetch_profile.py` выполняет GET-запрос к адресу `https://api.github.com/users/<login>`, где `<login>` - URL-кодированный логин GitHub. Заголовки `Accept` и `User-Agent` описывают формат и назначение запроса, а таймаут `10` секунд не позволяет ждать сеть бесконечно. После ответа проверяется, что JSON является объектом и содержит строковое поле `login`.

Обрабатываются HTTP-ошибки, недоступность сети и таймаут, ошибки данных и файлового доступа. Сетевой запрос выполняется только при прямом запуске файла, поэтому импорт модуля тестами не обращается к интернету. При отсутствии сети использован учебный локальный файл `profile_sample.json` с данными `{"login": "demo", "id": 1, "name": null}`; `null` читается Python как `None` и не заменяется выдуманным значением.

Автоматические проверки запускаются из папки `lab11`:

```bash
python3 test_analysis.py
```

Основная программа запускается так:

```bash
printf '5\n2\n' | python3 main.py
```

Ожидаются лидеры `[5, 10]`, идентификаторы задач лидеров `[1, 3, 4, 5]` и выборка варианта `[1]`. Все фактические результаты совпали с ожидаемыми.

## Вывод

В работе JSON отделён от Python-представления данных: `true` и `false` преобразуются в `True` и `False`, а `null` - в `None`. Структура проверяется отдельно от синтаксического разбора. Словари удобны для подсчётов и записей задач, список сохраняет порядок, а сортировка лидеров делает вывод воспроизводимым. Сетевой запрос изолирован от локального анализа и не выполняется при импорте тестами.
